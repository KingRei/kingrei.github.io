Python 100days - Day 20 - Divide and conquer, twice - merge sort, quick sort, and going parallel / 分治排序：merge sort、quick sort，以及它們的平行版

這兩個演算法都是把陣列切一半再遞迴，也都是 O(n log n)。差別只有一件事：力氣花在哪裡。 Merge sort 按照 index 硬切，所有成本都在合併；Quick sort 把成本全砸在 partition，合併則完全免費。

Python 100days - Day 17 - Negative weights and all pairs - Bellman-Ford, SPFA, Floyd-Warshall / 負權與全點對：Bellman-Ford / SPFA / Floyd-Warshall

昨天的 heap_greedy 骨架裡藏了一句沒有明講的理由：任何通往這個節點的其他路線，都必須經過 還留在 heap 裡的某個節點，而那個節點的距離已經不小於它，再多接幾條邊只會更長。 Dijkstra 的所有保證都建立在這句話上，而這句話建立在一個前提上——多加一條邊，不會讓路徑變短。

只要權重可以是負的，這句話就不成立了。而真正麻煩的是：Dijkstra 不會告訴你。 沒有例外、沒有無窮迴圈、沒有警告，它就是回傳一個長得跟答案一模一樣的數字。

三個節點的圖，邊是 A->B = 5、A->C = 2、B->C = -10，Dijkstra 給你 C = 2。 正確答案是走 B 的 -5。今天整篇文章都是為了處理這件事。

先講結論再講原理：一個函式、一個 heap、一個迴圈，用一個 key 參數決定你拿到的是哪一個演算法。 key 比的是「這一條邊多重」就是 Prim，比的是「從起點走過來總共多長」就是 Dijkstra。 其他部分——heap、done 陣列、放鬆（relax）、複雜度——完全一樣。

Typically, the domain of a hash function (the set of possible keys) is larger than its range (the number of different table indices), and so it will map several different keys to the same index which could result in collisions.

In another strategy from chaining, called open addressing. When a new entry has to be inserted, the buckets are examined, starting with the hashed-to slot and proceeding in some probe sequence, until an unoccupied slot is found. When searching for an entry, the buckets are scanned in the same sequence, until either the target record is found, or an unused array slot is found, which indicates that there is no such key in the table.The name "open addressing" refers to the fact that the location ("address") of the item is not determined by its hash value.

Python 100days - Day 03 - Tree / 樹

In computer science, a tree is a widely used abstract data type (ADT) that simulates a hierarchical tree structure, with a root value and subtrees of children with a parent node, represented as a set of linked nodes.

A binary search tree is a rooted binary tree, whose internal nodes each store a key (and optionally, an associated value) and each have two distinguished sub-trees, commonly denoted left and right. The tree additionally satisfies the binary search property, which states that the key in each node must be greater than or equal to any key stored in the left sub-tree, and less than or equal to any key stored in the right sub-tree. The leaves (final nodes) of the tree contain no key and have no structure to distinguish them from one another.
